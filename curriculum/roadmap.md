# Kotlin 8주 로드맵

> Java/Spring 백엔드 개발자가 **"Kotlin 써봤어요"에서 "Kotlin으로 짭니다"로** 넘어가는 8주.

## 전제

| | |
|---|---|
| 학습량 | 하루 1시간 × 주 5일 = **주 5시간, 총 40시간** |
| 출발점 | Java/Spring 실무 경험 있음, Kotlin은 문법만 훑어본 수준 |
| 도착점 | Kotlin + Spring Boot 3.3 으로 API를 처음부터 설계·구현하고, 면접에서 선택 근거를 방어할 수 있음 |
| 도구 | `kotlinc 2.4.10 (JRE 21)`, 학습 서버(`node server.ts`, :3838), IntelliJ |

## 설계 원칙

**1. 문법이 아니라 "Java에서 불편했던 것"을 축으로 배운다.**
`when`의 문법을 외우는 게 아니라, enum + switch로 상태를 표현하다 런타임 버그를 만든 경험을 sealed class로 푸는 순서다.

**2. 매주 손으로 친다.**
레슨마다 연습 문제가 있고, 기대 출력과 대조 채점된다. 읽고 끄덕이는 건 학습이 아니다.

**3. 실무에서 실제로 터지는 함정을 우선한다.**
`@field:NotBlank` 를 빠뜨려 검증이 조용히 무시되는 사고, allOpen 없이 `@Transactional` 이 안 먹는 사고 — 이런 게 문법 지식보다 먼저다.

**4. 8주 끝에 이력서에 쓸 게 남는다.**
졸업 과제(L24)는 연습이 아니라 포트폴리오다.

## 3단계 구조

### Phase 1 — 언어 (Week 1~3, L1~L9)
Java 개발자가 Kotlin에서 **사고방식을 바꿔야 하는 지점**들. 여기를 대충 넘기면 평생 "Java를 Kotlin 문법으로 쓴 코드"를 쓰게 된다.

### Phase 2 — 동시성 (Week 4~5, L10~L15)
코루틴. **Kotlin을 쓰는 가장 큰 이유**이자, 면접에서 가장 깊게 파고드는 주제. 스레드풀 고갈, 구조적 동시성, 취소 전파를 언어로 설명할 수 있게 된다.

### Phase 3 — 실전 (Week 6~8, L16~L24)
Spring Boot + JPA를 Kotlin으로 쓸 때만 존재하는 함정들. 그리고 졸업 과제.

## 각 Phase 종료 체크포인트

**Week 3 종료 —** 다음에 답할 수 있는가?
- `String`과 `String?`이 다른 타입이라는 게 실무에서 무엇을 막아주나?
- 확장 함수는 진짜로 클래스에 메서드를 추가하는가? (아니라면 어떻게 동작하나)
- Kotlin의 `out`/`in`이 Java의 `? extends`/`? super`와 다른 점은?

**Week 5 종료 —**
- 스레드 1000개와 코루틴 1000개의 차이를 메모리 관점에서 설명할 수 있나?

- `Flow`는 왜 `flowOn`으로 업스트림만 바꿀 수 있고 다운스트림은 못 바꾸나?

**Week 8 종료 —**
- 왜 JPA 엔티티에 data class를 쓰면 안 되나?
- `@Transactional`이 붙었는데 트랜잭션이 안 걸리는 경우 3가지는?
- 코루틴과 가상 스레드 중 무엇을 언제 쓰나?

## 면접관 시점 코멘트

5년차에게 "Kotlin 문법 아세요?"라고 묻는 면접관은 없다. 묻는 건 이거다.

> "왜 Java 대신 Kotlin을 썼나요? 팀 러닝커브 비용을 감수할 만한 이유가 뭐였죠?"

이 질문에 "간결해서요"라고 답하면 거기서 끝난다. 8주 뒤에는 이렇게 답할 수 있어야 한다 —
**"런타임 NPE를 컴파일 타임으로 당겼고, sealed class로 상태 분기 누락을 컴파일러가 잡게 했고, 코루틴으로 스레드풀 고갈 없이 I/O 병렬성을 확보했습니다. 대신 allOpen 플러그인 같은 Spring 연동 함정이 있어서 초기에 이런 사고가 있었고 이렇게 잡았습니다."**

마지막 문장이 핵심이다. **트레이드오프를 말할 수 있는 사람이 시니어로 보인다.**
